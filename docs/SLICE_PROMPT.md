early on, and otherwise expects you to run autonomously to the end. When you finish he will pick up
his Logitech pad, start the game, talk to a couple of NPCs, and fight on a moon and in a warp

2. `docs/ARCHITECTURE.md` — repo layout, assemblies, data model, runtime, art lanes, verification.

4. `C:\Users\natem\.claude\skills\generated-3d-characters\SKILL.md` and its `references\`
   (`prompt-craft.md`, `unity-intake.md`, `tooling-traps.md`) — the model-generation laws, paid

5. `C:\Users\natem\Projects\FrostboundUnity\docs\CONTROLLER_SUPPORT.md` — the gamepad design you

The sibling project `C:\Users\natem\Projects\FrostboundUnity` is your parts bin for **code and

## Ground rules

1. **Generated art only.** Every character, portrait, enemy, ship, environment piece, texture,
   skybox, UI panel and icon is produced by you through the image-generation tool and the Meshy
   bridge. Owned packs may serve as blockout stand-ins (replaced before any LOOK gate), rigging
   donors (skeleton only), particle prefabs and textures, input glyphs, fonts, and sound. Write
   `ART_EXCEPTION <asset> <reason>` in `docs/PROGRESS.md` for anything else, and there should be
   nothing else.
2. **Nothing is done until it is seen.** A log line proves a scene loaded; only a rendered
   screenshot, opened with the Read tool, proves it looks right. Renders run with graphics on,
   twice, keeping the second. A 12 KB PNG is a black frame, not evidence.
3. **Verify the instrument before trusting its verdict.** Before believing any green gate, name
   the broken state that would make it red. If you cannot, it is not a gate.
4. **One approval gate with Nathan** (P1, the species and hero designs). Everything else is your
   call; make it, write it down in `docs/DECISIONS.md`, and keep moving. If you are blocked on
   something only Nathan can do (Unity licence sign-in, Meshy balance, an image tool failure),
   write the exact ask into `docs/PROGRESS.md` under **BLOCKED**, do everything that does not
   depend on it, and stop only when nothing is left.
5. **Budget.** Meshy: 1,200 credits for the slice. Every task's `consumed_credits` goes in
   `docs/art/gen-manifest.json`. Generate in the priority order in P3; if the balance runs out,
   the remaining rows ship as blockout stand-ins marked `ART_PENDING`, and you continue.
6. **Commit at every gate** (`git add -A; git commit`) with the gate name in the message. Never
   commit `art-src/`, `Builds/`, `Library/`, `tools/meshy/.env`.
7. **Every batch step has a hard timeout and a marker.** Unity 6 batchmode on this machine can
   deadlock in ILPP after a clean compile and can hang on exit after finishing its work. Use the
   copied `headless.ps1` (silence watchdog) and `exec.ps1` (marker watch, then kill). Judge FAIL
   only on `error CS` or `FAILED:`; Unity's licensing chatter says lowercase "failed validation".
8. **Only one Unity holds the project lock.** Do Blender, Meshy and image work while a Unity job
   runs; never launch a second.
9. **Write C# and long scripts with the Write tool**, not shell heredocs (apostrophes break them).
10. Windows paths in Python need `C:/` form and UTF-8 stdout; run `.ps1` through the PowerShell
    tool; the Bash tool's `cd` persists.

## The image-generation tool

Use it for every 2D image: species sheets, character references, portrait grids, tileable
textures, skybox panoramas, planet maps, UI panels, icons. Save every output under
`art-src/Generated/<batch>/refs/` with the prompt beside it as `<name>.prompt.txt`. If the tool is
unavailable for a given image, write the prompt to `docs/art/prompts/<name>.md`, add a BLOCKED row
naming the file path where the PNG must land, and continue.

evidence listed. Record gates in `docs/PROGRESS.md` as they close.

## Laws inherited from Frostbound (each one cost a day; do not relearn them)

- One MonoBehaviour per file, class name = file name, or scenes load with missing scripts.
- `CharacterController.minMoveDistance = 0` everywhere, or high-fps tests drop movement.
- `Shader.Find` returns null in players; every runtime shader needs a material asset in a
  built scene.
- `AssetDatabase.ImportPackage` is async and unreliable headless; extract `.unitypackage`
  tarballs into `Assets/` instead (GUIDs live in the `.meta` files).
- Batchmode enumerates zero input devices; a pad is proven only in a built player's log.
- `-nographics` renders nothing and still prints OK markers; renders and screenshots need
  graphics on, twice, keep the second.
- Meshy's spine bones are named top-down but parented bottom-up; map explicitly and gate on
  `avatar.isHuman`, never `isValid`.
- Meshy embeds the texture in the FBX and the bridge saves it beside it; strip one or Unity binds
  the wrong copy. Bind albedo by the leading name token; ambiguity is a hard stop.
- A T-pose plate proves nothing; pose from Idle before rendering a cast.
- Renderer bounds lie on rigged bodies; measure through bone matrices.
- Any numeric target with one bound is an instruction to maximise; bound both ends in prompts.
- Contact fusion in a reference image is unfixable after reconstruction; reject and re-prompt.
- Keep archives outside `art-src/Generated/<batch>` — staging enumerates it recursively.
- A gate that cannot fail the defect is not evidence.
- When the log says done but Unity has not exited, judge by the marker and kill the process.
- `GetComponent<T>()?.` does not short-circuit on Unity's fake null; use `TryGetComponent`.
- Never `Get-Content | Set-Content` a UTF-8 doc in PowerShell (silent mojibake); use the Edit tool.
