# C1 cached GPU values must remain visible — October 7

**C1 remains OPEN.** Offline inspection finds another evidence-checker defect: `compare_frame_timing` deduplicates cached frame timestamps, but formerly did so before validating their positive durations. A corrupt value on a repeated timestamp, or on timestamp zero, could be silently omitted. A changed positive value on one supposedly completed frame could also disappear.

Three controls fail against the original checker: a Unix-sized duration with a cached timestamp, the same value without a timestamp, and a 250 ms duration conflicting with an earlier 5 ms reading for the same frame. The correction validates every finite duration first, reports conflicting positive values and retains raw-positive sample count/p95/p99/worst separately from the existing distinct-frame statistics. It never converts an impossible value into a valid duration. All **149 offline checks** pass; original-red output and original source are retained.

[The read-only recheck](C1-cached-gpu-values.json) of all six October 7 headroom runs preserves their outcomes. No conflicting-positive duplicates appear in those captures. Initial Decks release and both Tallow development attempts each retain their one impossible sample; Decks development/release-repeat and Tallow release acquire no additional API rejection. Original `analysis.json` files and CSVs are unchanged and hashed. This closes a validation hole, not the runtime corruption or the two rejected Decks stability loops. Native/Stopwatch epoch and asynchronous-frame limitations from [the synchronized-clock report](C1-synchronized-clocks.md) still apply.
